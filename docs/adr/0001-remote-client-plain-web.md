# 远程端使用纯静态 Web 单页而非 Flutter Web

远程端需要在浏览器中重建目标应用的真实 DOM（DOM 重绘模式）并直接下发鼠标键盘事件，Flutter Web 的 canvas 渲染路线与此天然冲突——它把页面画进自己的引擎，无法低成本地做 DOM 级重建与命中测试。决定：只有启动器（宿主控制面）使用 Flutter，远程端为无框架的静态 HTML/JS 单页，由宿主直接伺服。

## Consequences

- 后端与 web 端技术选型与 Flutter 解耦，另行调研（见地图工单「宿主中转后端技术选型」）。
- 仓库内会同时存在 Dart（Flutter 宿主）与 Web（远程端）两套技术栈，但远程端无构建链，保持纯静态文件。
