# 中转安全模型：全接口监听、访问密钥与可固定的 token

2026-11-10，根据用户要求，远程访问改为监听所有 IPv4 接口，不再绑定第一张 LAN 网卡。默认仍监听 `127.0.0.1`，开启“允许远程访问”后监听 `0.0.0.0`。复制链接优先使用本机非回环地址；经域名、隧道或端口转发访问时，可自行替换链接的主机地址。

宿主自动生成并保存访问密钥，也允许用户设置密钥。浏览器先提交密钥，通过后获得会话 cookie，才能读取远程页面、静态资源及连接 WebSocket。cookie 使用 HttpOnly 和 SameSite=Strict。WebSocket 首条消息仍须携带正确 token；浏览器的 Origin 必须与 Host 一致，包含端口。本机回环模式继续校验 Host 清单。

token 默认每次启动生成。开启“固定 token”后保存当前 token，跨中转及应用重启保留，直到手动轮转或取消固定。轮转 token 或修改密钥会撤销全部登录状态并断开现有连接。停止中转会断开连接并撤销登录状态；固定 token 的保存值继续保留。访问 URL 仍通过 `#t=<token>` fragment 携带 token，不进入 HTTP 请求行。

宿主 UI 启动的中转始终启用密钥校验。底层 `RelayServer.start` 的 `accessKey` 参数可省略，供仓库内脚本及协议测试维持仅 token 校验的接入方式。

## Consequences

- CDP 连接可控制目标应用，访问密钥与 token 均须保密。
- 密钥与固定 token 保存在宿主本地偏好设置中；浏览器只保存会话 cookie。
- 中转本身提供 HTTP。跨不可信网络时，应使用 HTTPS 代理或加密隧道，保护密钥和画面传输。
- 固定 token 的有效期由用户手动管理。轮转后，远程端须重新获取链接并验证密钥。
