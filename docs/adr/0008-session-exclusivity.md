# 每个目标页同时只允许一个会话（DOM 重绘与画面流互斥）

DOM 重绘与画面流两种模式各自接管 `relay.onClientMessage` 等全局回调，并存会互相抢消息。决定：一期互斥——启动会话时若另一会话存活直接报错；模式切换与 shell 页签切换都是「停旧会话 → attach 目标 → 起新会话」的重建流程；`switchTarget` 必须先校验目标在已枚举清单内，再停旧会话（先停后校验会把正常会话打掉）。

## Consequences

- 切换有数百毫秒级重建开销，可接受；双模式并存留待有真实需求再议。
- 会话停止必须在页面侧执行清理（`__gciCollector.stop()` + 摘除标志位），且清理失败不阻塞停止流程。
